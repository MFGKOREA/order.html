# 🧭 설계: 어사이드가 운전하고, 코드가 읽는다

쓴 날: 11.28 · 쓴 사람: 클로드 코드 · 코드: [`aside/`](../../aside/) · 검증 결과: [`verify-report.md`](verify-report.md)

## 1. 한 줄 결론

GW Agent(크롬 확장)가 하던 일을 둘로 나눕니다.

| 일 | 지금 (GW Agent) | 옮긴 뒤 |
|---|---|---|
| **운전** — 언제 무엇을 받을지 정하기, 창 열기, 로그인 상태 보기, 끝났는지 지켜보기, 안 되면 알리기 | 확장의 `bg.js` | **어사이드 + 책상 화면** |
| **읽기·입력** — MIS 화면에서 표를 읽어 시트에 넣기, 주문등록에 수량 넣고 저장 | `mis-sales.js` · `mis-agent.js` · `mis.js` | **그대로** (같은 코드를 어사이드 브라우저에서 돌림) |

어사이드(AI)는 숫자를 읽거나 옮겨 적지 않습니다. 창을 열고, 코드 한 줄을 실행하고, 닫습니다.

## 2. 왜 이렇게 하나

1. **읽는 코드는 이미 있고 검증돼 있습니다.** 확장 없이도 도는 코드입니다(확장이 생기기 전에는 북마크로 켰습니다). 확장은 그 코드를 "넣어 주는 껍데기"입니다. 바꿀 것은 껍데기입니다.
2. **AI가 표를 직접 옮기면 못 씁니다.** 입고현황 31일 치는 1,000줄이 넘습니다. 칸 하나를 5,000번에 한 번만 틀려도 표 3개 중 2개가 틀립니다. 두 번 읽어 맞춰 보는 방법도 표가 크면 맞는 날이 거의 없습니다([검증 결과](verify-report.md) 5번).
3. **KM 규칙 5번**("정해진 조회는 코드로, AI는 예외와 판단만")과 맞습니다.

## 3. 무엇이 어디서 도나

```
                    ┌──────────── 매장 PC · 어사이드 브라우저 ────────────┐
 KM ─ 말 ─▶ 클로드   │  탭 1: 책상 화면 (desk.html)   ← 항상 열어 둠       │
   · 그록 봇 ─ 설정 ─┼─▶ "지금 할 일" 한 가지를 보여 줌                     │
        (시트)       │        ▲ 어사이드가 3~5분마다 보고 그대로 함         │
                    │  탭 2: MIS (읽을 때만 엶)                            │
                    │     └ 시작 코드(starter.js) → 읽기 코드(mis-sales.js) │
                    │  탭 3: MIS 주문등록 (발주 대기 · 실제 단계에서만)     │
                    │     └ 시작 코드 → 자동 대기(mis-agent.js → mis.js)    │
                    └──────────────────────┬───────────────────────────────┘
                                           ▼
                                  발주 시트 (지금 쓰는 그 시트)
```

| 부품 | 파일 | 하는 일 |
|---|---|---|
| 책상 판단 | `aside/desk-core.js` | "지금 어사이드가 무엇을 해야 하나" 한 가지를 정함. 언제 받을지는 새로 만들지 않고 label-list 의 판단(`autoPlan`·`periodDue`)을 그대로 부름 |
| 책상 화면 | `aside/desk.html` | 20초마다 시트 상태를 보고 판단을 화면에 보여 줌. 시트 쓰기는 판단이 시킨 것만 |
| 시작 코드 | `aside/starter.js` | MIS 첫 화면에서 한 번 실행. 읽기 코드나 발주 대기 코드를 불러 옴 |
| 검증 | `aside/verify-core.js` | 읽은 값과 시트 값을 맞춰 보고 "같음/다름 몇 건"만 남김 |
| 기능 시험 | `aside/selftest.html` | 매장 PC 어사이드가 할 수 있는 일을 화면이 스스로 채점 |

## 4. 어사이드가 하는 일은 여섯 가지뿐

책상 화면 맨 위 상자에 한 가지만 뜹니다. 어사이드는 3~5분마다 이 상자를 보고 그대로 합니다.

| 글 | 뜻 | 어사이드가 할 일 |
|---|---|---|
| 할 일 없음 (IDLE) | 쉼 | 아무것도 안 함 |
| 읽기 시작 (READ) | 받을 것이 있음 | GW → [경영정보] → MIS 첫 화면 → 책상의 '시작 코드' 실행 |
| 기다리기 (WAIT) | 코드가 읽는 중 | 아무것도 안 누름 |
| 탭 닫기 (CLOSE) | 끝남 | 읽기에 쓴 MIS·GW 탭 닫기 |
| 발주 대기 켜기 (ARM) | 발주 대기 탭이 꺼짐 | MIS 첫 화면 → '시작 코드' 실행 → 그 탭은 열어 둠 |
| 멈춤 (STOP) | 잇달아 실패·막힘 | 아무것도 안 하고 KM 에게 알림 |

막히면 어사이드는 책상의 [막힘] 단추 셋 중 하나를 누릅니다(로그인 창 · GW 가 안 열림 · 시작 코드 실행 안 됨).

## 5. 세 가지 방식

시트의 `asideCfg` 한 칸으로 정합니다. 없으면 꺼짐입니다.

| 방식 | 무엇을 하나 | 시트에 쓰는 것 | GW Agent |
|---|---|---|---|
| **꺼짐** | 아무것도 안 함 | 없음 (0번) | 그대로 |
| **섀도** | 정한 시각에 같은 화면을 한 번 더 읽어 GW Agent 가 넣은 값과 맞춰 봄 | `aside…` 로 시작하는 칸만. 진짜 자료·요청 칸은 한 글자도 안 바꿈 | 그대로 (같이 돎) |
| **실제** | 읽기·발주를 어사이드가 맡음 | GW Agent 가 쓰던 칸 그대로 | **꺼야 함** (둘이 같은 요청을 받으면 안 됨) |

섀도가 안전한 까닭 (모두 시험으로 확인):
- 요청을 `asidePush` 라는 다른 칸으로 받습니다. GW Agent 는 이 칸을 모릅니다.
- 읽기 코드가 시트에 쓰려는 것을 시작 코드가 가로채 모아 두고, 시트의 값과 맞춰 본 뒤 버립니다.
- 직원 폰으로 가는 알림(라인체크)도 가로채 보내지 않습니다.
- 발주는 섀도로 하지 않습니다(저장이 일어나므로).

## 6. 새로 생기는 시트 칸 (모두 작고, 매장 숫자가 없음)

| 칸 | 누가 씀 | 내용 |
|---|---|---|
| `asideCfg` | KM · 클로드 코드 | 방식(꺼짐/섀도/실제), 섀도 종류·시각 |
| `asidePush` | 책상 · 시작 코드 | 섀도 요청과 진행 (진짜 요청 칸 `salesPush` 와 같은 모양) |
| `asideShadow` | 시작 코드 | 섀도 결과: 같음·다름·없음 건수와 다른 키 이름 (최근 40번) |
| `asideDesk` | 책상 | 책상이 살아 있다는 소식 (1시간에 한 번 + 바뀔 때) |
| `asideDiag` | 책상 | 멈춘 까닭 한 줄 |
| `asideSelftest` | 기능 시험 화면 | 됨/안 됨 한 줄 (KM 이 시켰을 때만) |

## 7. 안전장치

| 장치 | 내용 |
|---|---|
| 이 PC 한도 | 책상은 **그 PC 에서 KM 이 직접 허락한 데까지만** 움직임(보기만 / 섀도까지 / 실제까지). 폰·집 PC·남이 책상 주소를 열면 보기만 되고 시트에 0번 씀 |
| 발주 시간대 | 12:30~14:45 에는 읽기 요청을 내지 않음 (지금 규칙 그대로) |
| 발주 먼저 | 폰 전송이 들어오면 읽기는 기다림 |
| 폰이 안 갇힘 | 어사이드가 10분 안에 시작 못 하거나 14분 안에 못 끝내면 요청에 오류를 적어 폰을 풀어 줌. 쉬는 중에 들어온 요청, 쓰기가 사라진 요청도 나중에 거둠 |
| 3회 멈춤 | 잇달아 3번 실패하면 멈추고 `asideDiag` 에 한 줄. 60분 쉬고 한 번 다시, 또 실패하면 120분… (최대 4시간). 성공하면 풀림 |
| 발주는 따로 | 읽기가 고장 나 쉬는 중이어도 발주 대기 탭은 다시 켜게 함 |
| 확장과 겹침 | 실제 방식인데 GW Agent 확장 소식이 보이면 책상이 물러섬 |
| 시트 주소 | 이 저장소에 적지 않음. 화면이 발주앱 코드에서 찾아 씀 |

## 8. 아직 모르는 것 · 못 만든 것 (숨기지 않음)

**매장 PC 에서 확인해야 아는 것** → [`runbook-store-pc.md`](runbook-store-pc.md) 의 기능 시험으로 확인
| # | 모르는 것 | 안 되면 |
|---|---|---|
| 1 | 어사이드가 MIS 탭에서 **코드 한 줄을 실행**할 수 있는지 | 북마크로 실행 → 그것도 안 되면 어사이드에 "코드만 넣어 주는 작은 확장"을 설치 |
| 2 | 어사이드와 크롬(GW Agent)이 **같은 GW 계정으로 동시에** 들어가도 되는지 | 섀도를 GW Agent 가 쉬는 시각으로만, 또는 크롬을 잠깐 끄고 시험 |
| 3 | 어사이드가 **정해진 간격으로 스스로** 책상을 보는지(Routines) | KM 이 시킬 때만 도는 반자동으로 시작 |
| 4 | 뒤에 깔린 탭에서도 책상이 제때 도는지 | 책상 탭을 따로 창으로 띄워 둠 |

**아직 안 만든 것** (그래서 지금은 "실제"로 완전히 넘어갈 수 없음)
| 일 | 지금 | 필요한 것 |
|---|---|---|
| 근태 읽기(1시간마다 플젝 HR) · 근태 보내기 | GW Agent 만 함 | 같은 방식으로 옮기기 (다른 사이트 · 개인정보라 KM 결정 먼저) |
| 마감 기록(21:20 `daySnap`) | GW Agent 만 함 | 책상으로 옮기기 (MIS 를 안 여는 일이라 쉬움) |
| GW 자동 로그인 | 확장이 저장된 비밀번호로 | 어사이드의 로그인 저장에 기댐 (비밀번호는 KM 만) |

실제 방식은 GW Agent 를 꺼야 하는데, 끄면 위 세 가지도 같이 멈춥니다. 그래서 **지금 바로 할 수 있는 것은 섀도**이고, 실제로 넘어가기 전에 위 세 가지를 마저 옮겨야 합니다.

**바뀌지 않는 것**
- 매장 인터넷·VPN 이 끊기면 어사이드도 GW 에 못 들어갑니다. 지금 GW Agent 가 늦는 큰 까닭이 이것으로 보입니다(진단 칸에 "GW에 연결 안 됨"이 며칠 남아 있었음). 어사이드로 바꿔도 끊김 자체는 안 고쳐집니다. 대신 멈추면 바로 `asideDiag` 에 남아 알릴 수 있습니다.

## 9. 실시간 명령은 어떻게 되나

| 길 | 지연 | 상태 |
|---|---|---|
| 폰 [GW 전송] → 발주 대기 탭 | 20초 안 (AI 안 거침) | 실제 단계에서 |
| 폰 [불러오기] → 책상 → 어사이드 | 어사이드가 책상을 보는 간격 + 2분쯤 (5분 간격이면 가운데 5분) | 실제 단계에서 |
| KM → 클로드 → `asideCfg` → 책상 | 30분 안 (책상의 [설정 다시 읽기]를 누르면 바로) | 지금 됨 |
| KM → 클로드·그록 봇 → 어사이드에 바로 명령 (`aside exec --host`) | 바로 | 어사이드에 그 기능이 있는지 확인 뒤 |

## 10. 더 좋아질 수 있는 것 (label-list 쪽 일이라 여기서는 못 고침)

1. 발주 시트의 가벼운 상태 읽기(`status=1`)에 `asideCfg`·`asidePush`·`asideDesk` 를 더하면, 책상이 1MB 넘는 시트 전체를 읽을 일이 거의 없어지고 설정이 20초 안에 반영됩니다.
2. 규칙 원본(`ai-protocol.md`·상시 규칙)의 어사이드 자리를 "매장 PC · 시작 코드 실행"으로 고쳐야 합니다.
3. 시작 코드·책상은 MIS 로그인 화면 안에서 도는 코드를 부릅니다. 지금 읽기 코드가 label-list 에 있듯, 자리가 잡히면 `aside/` 도 label-list 로 옮겨 한 저장소에서 관리하는 편이 안전합니다(이 저장소에 쓸 수 있는 사람 = MIS 화면에 코드를 넣을 수 있는 사람).
4. 발주 시트 주소가 공개 저장소에 있어 누구나 읽고 쓸 수 있는 문제(가게 키)는 그대로입니다. KM 결정 사항으로 label-list 에 적혀 있습니다.
