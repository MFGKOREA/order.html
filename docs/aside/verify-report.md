눈여겨볼 확인:
- **섀도는 시트를 안 바꿉니다.** 섀도를 돌린 앞뒤로 진짜 자료 칸과 진짜 요청 칸이 한 글자도 안 바뀌었습니다.
- **섀도는 다름을 잡습니다.** 시트의 하루 수량을 1만 바꿔 둬도 "다름 1"로 나왔고, 하루치가 없으면 "없음 1"로 따로 셌습니다.
- **섀도는 알림을 안 보냅니다.** 라인체크가 알림을 보내려 할 때 막았습니다(막은 요청 1건, 실제로 나간 알림 0건).
- **확장 없이 발주가 됩니다.** 책상이 "발주 대기 켜기"를 띄움 → 시작 코드 실행 → 폰 전송 → 가짜 MIS 에 수량이 맞게 저장됨.
- **허락 안 한 PC 는 보기만 합니다.** 섀도 설정이어도 시트 쓰기 0번.

## 6. 되돌려 보기 ③ AI 가 숫자를 직접 옮겨 적으면

입고현황 31일 치(진짜 줄 수: 1,000줄 넘음 · 칸 4,312개)를 AI 가 보고 옮긴다고 치고, 칸 하나 틀릴 확률을 바꿔 봤습니다(**가정**).

| 칸 하나 틀릴 확률 | 한 번 읽어 틀린 표 | 합계 대조 뒤에도 틀린 채 들어감 | 두 번 읽어 서로 같을 확률 |
|---|---|---|---|
| 0.02% (5,000번에 한 번) | 64% | 34% | 13% |
| 0.1% | 99% | 18% | 0% |
| 0.5% | 100% | 1.1% | 0% |
| 1% | 100% | 0.9% | 0% |

→ 큰 표는 AI 가 직접 옮길 수 없습니다. 틀린 표가 대부분이고, 두 번 읽어 맞춰 보려 해도 맞는 날이 거의 없어 그날 값을 못 넣습니다.
→ 숫자 한 칸(오늘 Gross)은 다릅니다. 1% 틀려도 두 번 읽으면 98%는 맞고, 맞았는데 틀린 경우는 0.0001% 아래입니다.
→ 그래서 **표는 코드가 읽고**, AI 는 창만 엽니다. 어사이드가 실제로 얼마나 틀리는지는 기능 시험 4번(표 옮겨 넣기)으로 잽니다.

## 7. 되돌려 보기가 찾아 준 것 (고친 것)

| 찾은 것 | 고친 것 |
|---|---|
| 읽는 중에 새 요청이 오면 읽기 코드는 새 요청을 이어받지 않는데, 책상은 이어받는다고 봄 | 확장처럼 "탭 닫고 새로 시작" |
| 책상이 쉬는 동안 들어온 요청이 답 없이 남음 | 3분 뒤 오류를 적어 폰을 풀어 줌 |
| 어사이드가 [막힘]을 누르면 하던 요청이 그대로 남음 | 그 요청에 오류를 적고 접음 |
| 오류 쓰기가 인터넷 끊김으로 사라지면 요청이 영영 남음 | 나중에 다시 거두는 규칙 |
| 3번 실패하면 다음 날까지 멈춤 → 잠깐 끊겨도 하루를 버림 | 60분 쉬고 다시(2배씩, 최대 4시간) |
| 읽기 고장이 발주 대기까지 막음 | 쉬는 중에도 발주 대기 탭은 다시 켬 |
| 책상 주소를 여러 곳에서 열면 책상이 여럿이 됨 | 이 PC 한도(허락한 PC 만 움직임) |
| 시트가 1MB 를 넘어 자주 읽기 무거움 | 판 번호만 먼저 보고, 바뀌었을 때만 전체를 읽음 |
